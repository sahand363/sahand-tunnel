# 🛡️ Sahand Tunnel (`sahand-tunnel`)

این پروژه با هدف فعالیت در محیط‌های شبکه‌ای دارای اختلال، محدودیت و فیلترینگ طراحی شده است. Sahand Tunnel یک **سرور ورودی (Master / ایران)** را با استفاده از یک توکن رمزنگاری‌شده با پیشوند `st1.` به یک یا چند **سرور خروجی (Agent / خارج)** متصل می‌کند.

سیستم به‌صورت خودکار روش‌های انتقال موجود را شناسایی و آزمایش می‌کند و از میان روش‌های قابل‌استفاده، گزینه مناسب را انتخاب می‌کند. هم‌زمان، ترافیک کاربران را از طریق مسیر ارتباطی فعال به سرویس مقصد انتقال می‌دهد.

این معماری امکان انتقال ترافیک سرویس‌هایی مانند X-UI، Xray، V2Ray، WireGuard و OpenVPN را فراهم می‌کند؛ با هدف جلوگیری از تداخل پورت‌های تونل با پورت‌های سرویس‌های محلی روی سرور مقصد.

## ✨ قابلیت‌ها و امکانات اصلی (Key Capabilities)

### ۱. معماری دو موتوره (Dual-Engine Architecture)

Sahand Tunnel از دو موتور مستقل تشکیل شده است که هرکدام وظیفه مشخصی بر عهده دارند:

- **موتور اول: موتور ارتباطی و حفظ اتصال (Carrier & Lifeline Engine)**
  - محدوده پورت‌های پیش‌فرض: `28001–28030`
  - بررسی مداوم وضعیت روش‌های ارتباطی
  - احراز هویت و تأیید اعتبار ارتباط میان Master و Agent
  - همگام‌سازی تنظیمات و اطلاعات موردنیاز
  - ایجاد و حفظ یک ارتباط رمزنگاری‌شده میان دو سرور

- **موتور دوم: موتور انتقال ترافیک (Traffic Forwarding Engine)**
  - محدوده پورت‌های پیش‌فرض: `32001–32030`
  - دریافت اتصالات ورودی TCP و UDP کاربران از طریق Master
  - انتقال ترافیک از مسیر ارتباطی فعال
  - تحویل مستقیم ترافیک به سرویس‌های محلی روی Agent، از طریق آدرس‌هایی مانند `127.0.0.1:<port>`

### ۲. مدیریت هوشمند پورت‌ها و جلوگیری از تداخل (Role-Aware Port Binding)

یکی از ویژگی‌های مهم معماری Sahand Tunnel، تفکیک دقیق وظایف Master و Agent در مدیریت پورت‌ها است.

- **Master (سرور ورودی):**
  - پورت‌های تعریف‌شده در بخش `ForwardPorts` را روی آدرس `0.0.0.0:<port>` باز می‌کند.
  - اتصالات ورودی کاربران را دریافت می‌کند.
  - ترافیک دریافتی را از طریق ارتباط فعال به Agent انتقال می‌دهد.

- **Agent (سرور خروجی):**
  - پورت‌های `ForwardPorts` را برای دریافت اتصالات ورودی تونل باز نمی‌کند.
  - هنگام خروج ترافیک از تونل، اتصال را به آدرس محلی `127.0.0.1:<port>` برقرار می‌کند.
  - ترافیک را به سرویس محلی مقصد تحویل می‌دهد.

این جداسازی باعث می‌شود پورت‌های ورودی سرویس‌هایی مانند X-UI و Xray در اختیار خود سرویس‌ها باقی بمانند و موتور تونل آن‌ها را اشغال نکند. در نتیجه، راه‌اندازی مجدد یا بارگذاری مجدد این سرویس‌ها نباید به دلیل تداخل پورت با خطای `address already in use` مواجه شود.

### ۳. پشتیبانی از ۲۴ روش انتقال (24 Genuine Transport Protocols)

Sahand Tunnel دارای یک کاتالوگ ۳۰ جایگاهی برای روش‌های انتقال است که ۲۴ جایگاه آن به روش‌های انتقال اختصاص یافته و ۶ جایگاه دیگر برای توسعه و افزودن روش‌های جدید در آینده رزرو شده‌اند.

این مجموعه شامل روش‌های مختلف مبتنی بر TCP، UDP، TLS، HTTP، QUIC و سایر معماری‌های ارتباطی است.

### ۴. جفت‌سازی رمزنگاری‌شده و مدیریت خودکار گواهی‌ها (Cryptographic Pairing & Auto-PKI)

فرآیند اتصال دو سرور از طریق یک توکن اختصاصی با پیشوند `st1.` انجام می‌شود.

در Master می‌توان با یک مرحله ساده، توکن اتصال را تولید کرد. بر اساس طراحی پروژه، این توکن شامل اطلاعات زیر است:

- اطلاعات مربوط به ۳۰ پورت ارتباطی موتور Carrier
- کلیدهای احراز هویت مبتنی بر `HMAC-SHA256`
- اطلاعات گواهی‌های جفت‌شده مبتنی بر `Ed25519` و `X25519`
- اطلاعات موردنیاز برای برقراری ارتباط امن میان دو سرور
- اطلاعات همگام‌سازی منطقه زمانی Master

### ۵. داشبورد مدیریتی واکنش‌گرا (Mobile-First Web Dashboard)

Sahand Tunnel دارای یک داشبورد مدیریتی تحت وب است که برای استفاده در موبایل و دسکتاپ طراحی شده است.

امکانات داشبورد عبارت‌اند از:

- **Ping اختصاصی برای هر روش انتقال:** بررسی وضعیت و تأخیر هر روش به‌صورت جداگانه.
- **Next Working Method:** جابه‌جایی سریع به روش انتقال بعدی که قابل استفاده باشد.
- **Batch Port Settings:** مدیریت گروهی تنظیمات پورت‌ها از طریق پنجره تنظیمات (آیکون چرخ‌دنده).
- **Lifeline History:** مشاهده تاریخچه ۲۰ رویداد اخیر مربوط به وضعیت ارتباطی.
- **Network Analytics:** نمایش آمار مصرف واقعی پهنای باند شبکه در بازه‌های ۷ و ۳۰ روزه.
- **Light / Dark Theme:** پشتیبانی از پوسته روشن و تاریک.
- **Real-Time Monitoring:** نمایش وضعیت ارتباط و اطلاعات عملکردی سیستم.

## 🚀 نصب و راه‌اندازی سریع (Quick Start & Installation)

### ۱. نصب خودکار با یک دستور (روش پیشنهادی)

برای نصب Sahand Tunnel باید اسکریپت نصب را روی هر دو سرور اجرا کنید:

- سرور ایران: **Master**
- سرور خارج: **Agent**

از طریق SSH به هر سرور متصل شوید و دستور زیر را اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sahand363/sahand-tunnel/main/install.sh)
```

در طول فرآیند نصب، اسکریپت به‌صورت تعاملی اطلاعات زیر را از شما دریافت می‌کند:

1. **نقش سرور (Node Role):**
   - روی سرور ورودی ایران، گزینه `Master` را انتخاب کنید.
   - روی سرور خروجی خارج از ایران، گزینه `Agent` را انتخاب کنید.

2. **پورت پنل مدیریتی (Panel Port):**
   - پورت موردنظر برای دسترسی به داشبورد تحت وب را انتخاب کنید.
   - محدوده مجاز: `1024–65535`
   - مثال: `18080`

3. **اطلاعات ورود مدیر (Administrator Credentials):**
   - نام کاربری و رمز عبور پنل مدیریتی را تعیین کنید.
   - حداقل طول رمز عبور: ۱۲ کاراکتر.

### ۲. اتصال Master و Agent (راه‌اندازی در حدود ۶۰ ثانیه)

پس از نصب نرم‌افزار روی هر دو سرور، مراحل زیر را برای اتصال آن‌ها انجام دهید.

**مرحله اول: ایجاد توکن در پنل Master**

وارد پنل مدیریتی سرور ایران شوید:

`http://<MASTER_IP>:<PANEL_PORT>`

- وارد حساب کاربری خود شوید.
- به بخش **Servers** بروید.
- در قسمت مربوطه، یک نام برای سرور خروجی وارد کنید؛ برای مثال `Germany-Agent`.
- آدرس IP سرور Agent را وارد کنید.
- روی گزینه **Generate Token** کلیک کنید.
- پس از ایجاد سرور، روی آیکون **Copy** در کارت مربوط به آن کلیک کنید تا توکن اتصال با پیشوند `st1.` کپی شود.

**مرحله دوم: اتصال Agent به Master**

وارد پنل مدیریتی سرور خارج شوید:

`http://<AGENT_IP>:<PANEL_PORT>`

- وارد حساب کاربری خود شوید.
- به بخش **Servers** بروید.
- آدرس IP سرور Master را وارد کنید.
- توکن اتصال `st1.` را در قسمت مربوطه قرار دهید.
- روی گزینه **Connect** کلیک کنید.

پس از برقراری موفق ارتباط، هر دو داشبورد باید وضعیت `CONNECTED` را نمایش دهند. همچنین روش انتقال فعال، پورت ارتباطی و میزان تأخیر قابل مشاهده خواهد بود.

**مرحله سوم: تنظیم انتقال پورت‌های X-UI و Xray**

- وارد پنل **Master** شوید.
- به بخش **Tunnels** بروید.
- روش انتقال موردنظر خود را باز کنید؛ برای مثال:
  - `01 WSS`
  - `08 QUIC`
  - `20 mTLS Stream`
  - `24 SAHAND-RAW`
- در قسمت **Forwarding Ports (CSV)**، پورت‌های ورودی سرویس‌های خود روی Agent را وارد کنید.

مثال:

```text
45001, 45002
```

- کلید فعال‌سازی روش انتقال را روی **ON** قرار دهید.
- روی **Save Settings** کلیک کنید.

اکنون کاربران می‌توانند به‌جای اتصال مستقیم به IP سرور خارج، از آدرس IP سرور Master و پورت تعیین‌شده استفاده کنند.

برای مثال:

```text
<MASTER_IP>:45001
```

## 📡 فهرست روش‌های انتقال (Transport Methods Catalogue)

Sahand Tunnel از ۲۴ روش انتقال با معماری‌ها و ویژگی‌های متفاوت پشتیبانی می‌کند.

| شناسه | نام روش انتقال | پورت پیش‌فرض | امنیت اعلام‌شده | نوع ترافیک | معماری پروتکل و رمزنگاری |
|---|---|---|---|---|---|
| **01** | **WSS** | `28001` | `95%` | `TCP` | WebSocket مطابق استاندارد **RFC 6455** روی TLS 1.2/1.3، با `ALPN: http/1.1`، فریم‌های باینری، Ping/Pong برای حفظ اتصال و Certificate Pinning مبتنی بر SHA-256 |
| **02** | **gRPC** | `28002` | `95%` | `TCP` | انتقال جریانی gRPC با فریم‌بندی HTTP/2 روی TLS و پیام‌های باینری دارای طول مشخص |
| **03** | **HTTP/2** | `28003` | `90%` | `TCP` | جریان‌های باینری چندگانه و Multiplex شده بر بستر HTTP/2 و TLS |
| **04** | **HTTP CONNECT** | `28004` | `76%` | `TCP` | تونل‌سازی با متد `CONNECT` مطابق RFC 9110 روی TLS |
| **05** | **HTTPS Proxy** | `28005` | `82%` | `TCP` | انتقال جریان داده از طریق یک حامل HTTPS Proxy روی TLS |
| **06** | **TCP Relay** | `28006` | `45%` | `TCP` | انتقال مستقیم TCP با ساختار سبک |
| **07** | **TLS Stream** | `28007` | `88%` | `TCP` | جریان ارتباطی پایدار و رمزنگاری‌شده با TLS 1.3 و Certificate Pinning |
| **08** | **QUIC** | `28008` | `92%` | `TCP+UDP` | پروتکل QUIC مطابق **RFC 9000** روی UDP، همراه با TLS 1.3، جریان‌های چندگانه و دیتاگرام‌های UDP مطابق RFC 9221 |
| **09** | **Rathole** | `28009` | `94%` | `TCP+UDP` | انتقال رمزنگاری‌شده مبتنی بر `Noise_NK_25519_ChaChaPoly_BLAKE2s` همراه با کانال کنترلی معکوس |
| **10** | **Noise TCP Stealth** | `28010` | `97%` | `TCP+UDP` | پروتکل `Noise_IK_25519_ChaChaPoly_BLAKE2s` همراه با مبهم‌سازی طول فریم‌ها |
| **11** | **Reverse TCP** | `28011` | `50%` | `TCP` | ایجاد مجموعه‌ای از سوکت‌های TCP معکوس و آماده‌به‌کار با آغاز اتصال از سمت Agent |
| **12** | **SOCKS5** | `28012` | `60%` | `TCP+UDP` | پروتکل SOCKS5 احراز هویت‌شده مطابق **RFC 1928 و RFC 1929** با پشتیبانی از `CONNECT` و `UDP ASSOCIATE` |
| **13** | **SSH Tunnel** | `28013` | `86%` | `TCP` | انتقال رمزنگاری‌شده SSH-2 مطابق **RFC 4251–4254** با استفاده از کانال‌های `direct-tcpip` |
| **14** | **Raw TCP** | `28014` | `35%` | `TCP` | ارتباط باینری بدون پیشوند متنی ASCII و انتقال مستقیم جریان TCP بدون فریم‌بندی |
| **15** | **UDP Relay** | `28015` | `40%` | `UDP` | انتقال دیتاگرام‌های UDP باینری با احراز هویت و یک حامل جریانی مکمل |
| **16** | **DNS Transport** | `28016` | `70%` | `TCP+UDP` | انتقال DNS بر اساس **RFC 1035** با پشتیبانی از UDP DNS و TCP DNS مطابق بخش 4.2.2 و کدگذاری Wire Format |
| **17** | **TLS over TCP** | `28017` | `84%` | `TCP` | انتقال TLS احراز هویت‌شده در لایه Record روی TCP |
| **18** | **HTTP Long Polling** | `28018` | `72%` | `TCP` | حامل انتقال HTTP/1.1 با ساختار دوکاناله و استفاده از `text/event-stream` |
| **19** | **WebTransport** | `28019` | `93%` | `TCP+UDP` | WebTransport مبتنی بر HTTP/3 Extended CONNECT روی QUIC و TLS 1.3، همراه با مسیر جایگزین |
| **20** | **mTLS Stream** | `28020` | `99%` | `TCP` | احراز هویت متقابل TLS 1.3 مطابق **RFC 8446** با گواهی‌های X.509 و `RequireAndVerifyClientCert` بر پایه PKI جفت‌شده Ed25519 |
| **21** | **TCP Multiplex** | `28021` | `68%` | `TCP` | Multiplexer جریان باینری به سبک Yamux با پیام‌های `StreamOpen`، `Data`، `Ping` و `FIN` روی یک سوکت TCP |
| **22** | **WebSocket Multiplex** | `28022` | `89%` | `TCP` | اتصال WebSocket باینری مطابق RFC 6455 با قابلیت انتقال چند جریان مستقل |
| **23** | **HTTP Upgrade** | `28023` | `74%` | `TCP` | مطابق **RFC 9110 Section 7.8** و Xray `httpupgrade`؛ استفاده از پاسخ `101 Switching Protocols` و سپس جریان باینری بدون فریم‌بندی |
| **24** | **SAHAND-RAW** | `28024` | `96%` | `TCP+UDP` | موتور انتقال Raw Packet با هدرهای TCP مطابق RFC 793، محاسبه Checksum مطابق RFC 1071، رمزنگاری X25519 و ChaCha20-Poly1305 AEAD، محافظت Anti-Replay با پنجره ۶۴ بسته، ARQ و Stream Multiplexing؛ با Backendهای `raw_ip`، `udp` و `auto` |
| **25–30** | *Reserved Slots* | `28025–28030` | — | — | جایگاه‌های رزروشده برای افزودن درایورهای انتقال جدید در نسخه‌های آینده |

> **توجه:** درصدهای امنیتی درج‌شده در جدول، مقادیر اعلام‌شده در مشخصات پروژه هستند و نباید به‌عنوان رتبه‌بندی استاندارد، احتمال نفوذ یا تضمین امنیت رمزنگاری در نظر گرفته شوند. امنیت واقعی هر روش به پیاده‌سازی، تنظیمات و شرایط عملیاتی آن بستگی دارد.

## 💻 دستورات کاربردی SSH (Useful SSH Commands Cheat Sheet)

### ۱. منوی مدیریت تعاملی (Interactive Management Menu)

برای دسترسی به منوی مدیریتی داخلی Sahand Tunnel، در هر زمان می‌توانید دستور زیر را اجرا کنید.

از طریق این منو می‌توانید نرم‌افزار را به‌روزرسانی کنید، وضعیت سرویس را بررسی کنید، پورت‌ها را تغییر دهید یا اطلاعات ورود را مدیریت کنید.

```bash
sudo sahand-tunnel menu
```

برای به‌روزرسانی فایل اجرایی از طریق GitHub Releases، دستور بالا را اجرا کرده و گزینه زیر را انتخاب کنید:

```text
7. Update
```

### ۲. مدیریت سرویس Systemd (Systemd Service Management)

با استفاده از دستورات زیر می‌توانید سرویس Sahand Tunnel را مدیریت کنید.

```bash
# بررسی وضعیت سرویس و مدت زمان فعالیت آن
sudo systemctl status sahand-tunnel

# راه‌اندازی مجدد Sahand Tunnel
sudo systemctl restart sahand-tunnel

# متوقف کردن سرویس
sudo systemctl stop sahand-tunnel

# اجرای سرویس
sudo systemctl start sahand-tunnel

# فعال‌سازی اجرای خودکار هنگام روشن شدن سرور
sudo systemctl enable sahand-tunnel
```

### ۳. مشاهده گزارش‌ها و عیب‌یابی (Live Logs & Troubleshooting)

برای مشاهده گزارش‌های عملکردی و بررسی خطاهای احتمالی می‌توانید از دستورات زیر استفاده کنید.

```bash
# مشاهده زنده گزارش‌ها
sudo journalctl -u sahand-tunnel -f

sudo journalctl -u sahand-tunnel -n 100 --no-pager

# فیلتر کردن گزارش‌های مربوط به انتخاب Backend در SAHAND-RAW

sudo journalctl -u sahand-tunnel --no-pager | grep -i "SAHAND-RAW"
```

### ۴. بررسی پورت‌ها و سوکت‌های شبکه (Port & Socket Verification)

برای بررسی پورت‌هایی که توسط Sahand Tunnel استفاده می‌شوند، می‌توانید از دستور `ss` استفاده کنید.

```bash
# نمایش تمام پورت‌های TCP و UDP که توسط sahand-tunnel باز شده‌اند
sudo ss -tulpn | grep sahand-tunnel

# بررسی پورت‌های موتور اول (28001 تا 28030)
sudo ss -tulpn | grep -E ':280[0-3][0-9]'

# بررسی پورت‌های پیش‌فرض موتور دوم در Master
# (32001 تا 32030)
sudo ss -tulpn | grep -E ':320[0-3][0-9]'

# بررسی پورت‌های ورودی سرویس Xray روی Agent
sudo ss -tulpn | grep xray
```

### ۵. تنظیم فایروال (Firewall Configuration)

اگر روی سرورهای شما فایروال `UFW` فعال است، باید پورت پنل مدیریتی، محدوده پورت‌های موتور اول و پورت‌های ورودی موتور دوم روی Master را مجاز کنید.

دستورات زیر برای باز کردن پورت‌های پیش‌فرض ارائه شده‌اند.

```bash
# باز کردن پورت‌های موتور اول (Carrier)
# روی هر دو سرور Master و Agent
sudo ufw allow 28001:28030/tcp
sudo ufw allow 28001:28030/udp

# باز کردن پورت‌های پیش‌فرض موتور دوم
# فقط روی سرور Master
sudo ufw allow 32001:32030/tcp
sudo ufw allow 32001:32030/udp

# بررسی قوانین فعال UFW
sudo ufw status numbered
```

**نکته مهم درباره SAHAND-RAW:**

در روش شماره ۲۴ یعنی `SAHAND-RAW`، هنگام استفاده از حالت `raw_ip`، نرم‌افزار به‌صورت خودکار قانون مربوط به جلوگیری از ارسال بسته‌های TCP با پرچم `RST` را در `iptables` مدیریت می‌کند.

برای بررسی این قانون می‌توانید از دستور زیر استفاده کنید:

```bash
# بررسی قوانین OUTPUT مربوط به جلوگیری از TCP RST
# برای پورت 28024
sudo iptables -L OUTPUT -v -n | grep 28024
```

### ۶. مشاهده تنظیمات و تهیه نسخه پشتیبان (Configuration & Backup)

فایل تنظیمات اصلی و اطلاعات آماری شبکه در مسیر داده‌های نرم‌افزار ذخیره می‌شوند.

برای مشاهده تنظیمات فعلی:

```bash
# مشاهده فایل تنظیمات
sudo cat /opt/sahand-tunnel/data/config.json
```

برای تهیه نسخه پشتیبان از تنظیمات و اطلاعات آماری پهنای باند:

```bash
# تهیه نسخه پشتیبان از تنظیمات
sudo cp /opt/sahand-tunnel/data/config.json ~/sahand-config-backup.json

# تهیه نسخه پشتیبان از آمار مصرف پهنای باند ۳۰ روزه
sudo cp /opt/sahand-tunnel/data/analytics.json ~/sahand-analytics-backup.json
```

## 🛠️ توسعه، ساخت و آزمایش از روی سورس کد (Building & Testing from Source)

این بخش برای توسعه‌دهندگان و افرادی در نظر گرفته شده است که قصد دارند Sahand Tunnel را مستقیماً از سورس کد دریافت، کامپایل و آزمایش کنند.

### پیش‌نیازها (Prerequisites)

برای ساخت پروژه به ابزارهای زیر نیاز دارید:

- **Go:** نسخه `1.26` یا بالاتر
- **Node.js و npm:** نسخه `20` یا بالاتر (برای ساخت داشبورد React موجود در پوشه `web/`)

### ساخت رابط کاربری و فایل اجرایی Go (Build Frontend & Go Binary)

ابتدا وارد پوشه رابط کاربری شوید و داشبورد React را بسازید.

```bash
# 1. ساخت رابط کاربری React
cd web

# نصب وابستگی‌ها
npm ci

# ساخت نسخه نهایی داشبورد
npm run build

# بازگشت به مسیر اصلی پروژه
cd ..
```

سپس وابستگی‌های Go را مرتب کرده و بررسی ایستای کد را اجرا کنید.

```bash
# 2. مرتب‌سازی ماژول‌های Go
go mod tidy

# اجرای بررسی استاتیک کد
go vet ./cmd/sahand-tunnel
```

در نهایت، فایل اجرایی نهایی را با تنظیمات مناسب برای محیط Production بسازید.

```bash
# 3. ساخت فایل اجرایی نهایی
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o sahand-tunnel ./cmd/sahand-tunnel
```

### اجرای تست‌ها و بنچمارک‌ها (Automated Tests & Benchmarks)

برای بررسی عملکرد، پایداری و صحت پیاده‌سازی بخش‌های مختلف پروژه، می‌توانید از دستورات زیر استفاده کنید.

```bash
# اجرای تمام تست‌های پروژه همراه با Race Detector
go test -v -race ./...
```

**تست اختصاصی WSS:**

```bash
# آزمایش امنیت، گواهی‌ها، Keepalive و Half-Close در RFC 6455 WSS
go test -v -race -run TestWSS ./cmd/sahand-tunnel
```

**تست اختصاصی SAHAND-RAW:**

```bash
# آزمایش Packet Codec، AEAD Replay، ARQ Loss/Reordering و Backendها
go test -v -race -run TestSahandRaw ./cmd/sahand-tunnel
```

**بنچمارک عملکرد SAHAND-RAW:**

```bash
# اندازه‌گیری سرعت Packet Encoding و رمزنگاری ChaCha20-Poly1305 AEAD
go test -bench=BenchmarkSahandRaw -benchmem -run=^$ ./cmd/sahand-tunnel
```
