# 🛡️ Sahand Tunnel

**Sahand Tunnel** یک موتور انتقال ترافیک و تونل‌سازی چندپروتکلی، با کارایی بالا و مقاوم در برابر محدودیت‌های شبکه است که با زبان **Go** توسعه داده شده و دارای یک داشبورد مدیریتی تحت وب مبتنی بر **React** است.

این پروژه با هدف فعالیت در محیط‌های شبکه‌ای دارای اختلال، محدودیت و فیلترینگ طراحی شده است. Sahand Tunnel با استفاده از یک ساختار دوطرفه، یک **سرور ورودی (Master / ایران)** را به یک یا چند **سرور خروجی (Agent / خارج)** متصل می‌کند.

اتصال میان سرورها از طریق یک توکن رمزنگاری‌شده با پیشوند `st1.` برقرار می‌شود. سیستم می‌تواند روش‌های انتقال موجود را شناسایی، آزمایش و از میان روش‌های قابل‌استفاده، گزینه مناسب را انتخاب کند و هم‌زمان ترافیک کاربران را به سرویس مقصد انتقال دهد.

این معماری برای انتقال پورت سرویس‌هایی مانند X-UI، Xray، V2Ray، WireGuard و OpenVPN طراحی شده است؛ بدون اینکه پورت‌های مورد استفاده سرویس‌های مقصد در سمت Agent با پورت‌های شنود تونل تداخل پیدا کنند.

## ✨ قابلیت‌ها و امکانات اصلی

### ۱. معماری دو موتوره (Dual-Engine Architecture)

Sahand Tunnel از دو موتور مستقل تشکیل شده است که هرکدام وظیفه مشخصی بر عهده دارند:

**موتور اول: موتور ارتباطی و حفظ اتصال (Carrier & Lifeline Engine)**

- پورت‌های پیش‌فرض: `28001–28030`
- برقراری ارتباط پایدار میان Master و Agent
- بررسی مداوم وضعیت روش‌های ارتباطی
- احراز هویت و تأیید اعتبار ارتباط میان دو سرور
- همگام‌سازی تنظیمات و اطلاعات موردنیاز
- حفظ ارتباط رمزنگاری‌شده میان دو سرور

**موتور دوم: موتور انتقال ترافیک (Traffic Forwarding Engine)**

- پورت‌های پیش‌فرض: `32001–32030`
- دریافت اتصالات ورودی کاربران از طریق Master
- انتقال ترافیک TCP و UDP از مسیر ارتباطی فعال
- تحویل ترافیک به سرویس مقصد روی Agent
- پشتیبانی از انتقال ترافیک به پورت‌های محلی سرویس‌ها، مانند `127.0.0.1:<port>`

### ۲. مدیریت هوشمند پورت‌ها و جلوگیری از تداخل (Role-Aware Port Binding)

یکی از ویژگی‌های مهم معماری Sahand Tunnel، تفکیک دقیق وظایف Master و Agent در مدیریت پورت‌ها است.

**Master (سرور ورودی):**

- پورت‌های تعریف‌شده در بخش `ForwardPorts` را روی آدرس `0.0.0.0:<port>` باز می‌کند.
- اتصالات ورودی کاربران را دریافت می‌کند.
- ترافیک دریافتی را از طریق ارتباط فعال به Agent انتقال می‌دهد.

**Agent (سرور خروجی):**

- پورت‌های `ForwardPorts` را روی شبکه عمومی یا رابط‌های ورودی تونل باز نمی‌کند.
- هنگام دریافت ترافیک، اتصال خروجی را به آدرس محلی `127.0.0.1:<port>` برقرار می‌کند.
- ترافیک را به سرویس محلی مقصد تحویل می‌دهد.

این جداسازی باعث می‌شود Agent مالک پورت‌های ورودی سرویس‌های محلی نباشد و در نتیجه، اجرای مجدد یا راه‌اندازی مجدد سرویس‌هایی مانند X-UI و Xray به دلیل اشغال پورت توسط موتور تونل با خطای `address already in use` مواجه نشود.

### ۳. مجموعه پروتکل‌های انتقال (Multi-Protocol Transport)

Sahand Tunnel دارای یک کاتالوگ ۳۰ جایگاهی برای روش‌های انتقال است که طبق مشخصات پروژه، شامل ۲۴ روش انتقال پیاده‌سازی‌شده است.

برخی از پروتکل‌ها و روش‌های در نظر گرفته‌شده عبارت‌اند از:

| پروتکل / روش | توضیحات |
|---|---|
| WSS (RFC 6455) | انتقال داده از طریق WebSocket رمزنگاری‌شده |
| gRPC | انتقال داده با استفاده از چارچوب gRPC |
| HTTP/2 | انتقال داده بر بستر HTTP/2 |
| QUIC (RFC 9000) | انتقال داده بر پایه پروتکل QUIC |
| Rathole (Noise_NK) | ارتباط تونلی مبتنی بر Noise |
| Noise TCP Stealth (Noise_IK) | ارتباط TCP با استفاده از Noise IK |
| WebTransport (HTTP/3) | انتقال داده با استفاده از WebTransport |
| mTLS Stream (TLS 1.3) | ارتباط رمزنگاری‌شده با احراز هویت دوطرفه |
| TCP Multiplex (Yamux) | مدیریت چند جریان ارتباطی روی یک اتصال TCP |
| WebSocket Multiplex | انتقال چند جریان داده از طریق WebSocket |
| HTTP Upgrade (RFC 9110) | ارتقای ارتباط HTTP به پروتکل دیگر |
| SAHAND-RAW | روش انتقال مبتنی بر Raw Packet، با ChaCha20-Poly1305 و ARQ |

> تعداد روش‌های فعال، وضعیت پیاده‌سازی و سازگاری عملیاتی هر پروتکل باید بر اساس نسخه واقعی نرم‌افزار بررسی شود.

### ۴. جفت‌سازی رمزنگاری‌شده و مدیریت خودکار گواهی‌ها (Cryptographic Pairing & Auto-PKI)

فرآیند اتصال دو سرور با استفاده از یک توکن اختصاصی انجام می‌شود.

در Master می‌توان با یک مرحله ساده، توکن جفت‌سازی با پیشوند `st1.` تولید کرد.

بر اساس طراحی پروژه، این توکن می‌تواند شامل اطلاعات زیر باشد:

- اطلاعات مربوط به ۳۰ پورت ارتباطی موتور Carrier
- کلیدهای احراز هویت مبتنی بر `HMAC-SHA256`
- اطلاعات گواهی‌های جفت‌شده مبتنی بر `Ed25519` و `X25519`
- اطلاعات لازم برای برقراری ارتباط امن میان Master و Agent
- اطلاعات همگام‌سازی منطقه زمانی Master

با انتقال این توکن به Agent، اطلاعات لازم برای شناسایی و برقراری ارتباط میان دو سرور در اختیار آن قرار می‌گیرد.

### ۵. داشبورد مدیریتی واکنش‌گرا (Mobile-First Web Dashboard)

Sahand Tunnel دارای یک پنل مدیریتی تحت وب با طراحی واکنش‌گرا است که برای استفاده در موبایل و دسکتاپ طراحی شده است.

امکانات داشبورد عبارت‌اند از:

- **Ping اختصاصی برای هر روش انتقال:** بررسی وضعیت و تأخیر هر روش به‌صورت جداگانه.
- **Next Working Method:** امکان جابه‌جایی سریع به روش ارتباطی بعدی که در دسترس است.
- **Batch Port Settings:** مدیریت گروهی تنظیمات پورت‌ها از طریق پنجره تنظیمات.
- **Lifeline History:** مشاهده تاریخچه ۲۰ رویداد اخیر مربوط به وضعیت ارتباطی.
- **Network Analytics:** نمایش آمار مصرف واقعی پهنای باند شبکه در بازه‌های ۷ و ۳۰ روزه.
- **Light / Dark Theme:** پشتیبانی از پوسته روشن و تاریک.
- **Real-Time Monitoring:** نمایش وضعیت ارتباط و اطلاعات عملکردی سیستم.

## 🚀 نصب و راه‌اندازی سریع (Quick Start)

### ۱. نصب خودکار با یک دستور (روش پیشنهادی)

برای نصب Sahand Tunnel، باید اسکریپت نصب را روی هر دو سرور اجرا کنید:

- سرور ایران: **Master**
- سرور خارج: **Agent**

از طریق SSH به هر سرور متصل شوید و دستور زیر را اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sahand363/sahand-tunnel/main/install.sh)
```

این دستور اسکریپت نصب را مستقیماً از مخزن رسمی GitHub دریافت و اجرا می‌کند.

**توجه:** فرآیند نصب باید روی هر دو سرور به‌صورت جداگانه انجام شود.
